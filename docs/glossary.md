# Glossary

[← Back to the main README](../README.md)

**API** — Application Programming Interface; a defined way for software components to interact.

**Branch** — In Git, a lightweight movable name pointing to a commit, commonly used to isolate a line of work.

**CI (Continuous Integration)** — Automatically building/testing/checking changes when code is integrated or proposed.

**CLI (Command-Line Interface)** — A program controlled using text commands in a terminal.

**Commit** — A recorded Git snapshot plus metadata such as author and message.

**Container** — An isolated running process/environment created from a container image.

**DAG (Directed Acyclic Graph)** — Nodes connected by directed edges with no cycles; often used to represent workflow dependencies.

**DataFrame** — A labelled, table-like data structure used by libraries such as pandas, Polars, Spark, and others.

**Dependency** — Software or data that another component requires.

**Endpoint** — A specific address/path exposed by a network API.

**ETL / ELT** — Extract–Transform–Load / Extract–Load–Transform; common patterns for moving and transforming data.

**Feature** — In machine learning, an input variable used by a model.

**Git** — Distributed version control system.

**GitHub** — Hosted collaboration platform built around Git repositories.

**HTTP** — Hypertext Transfer Protocol; the application protocol used for the web and many APIs.

**Idempotent** — An operation whose repeated execution has the same intended end state as one execution.

**JSON** — Text format for structured data with objects, arrays, strings, numbers, booleans, and null.

**Model** — A learned mathematical/statistical function or procedure used for prediction or discovering structure.

**Package** — Reusable software distributed for installation into other projects.

**Parquet** — Column-oriented file format widely used for analytical data.

**Pipeline** — A sequence of data-processing steps, often automated and repeatable.

**Primary key** — Column(s) intended to identify database-table rows uniquely.

**Pull request** — A proposed branch change presented for review and merging on platforms such as GitHub.

**Repository (repo)** — A Git project containing files and version history.

**Schema** — A description of data structure, commonly names, types, constraints, and relationships.

**SQL** — Structured Query Language, used with relational/analytical databases.

**Target / label** — In supervised machine learning, the value the model is trained to predict.

**Virtual environment** — Isolated Python environment used to keep one project's dependencies separate from another's.
