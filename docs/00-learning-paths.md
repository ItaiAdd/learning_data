# Learning Paths

[← Back to the main README](../README.md)

There is no single correct order for learning data science or data engineering. People arrive with different strengths: one student may be comfortable with calculus but new to programming, while another may build software confidently but have never taken statistics.

The paths below are **starting points, not prerequisites**.

## Path A — New to programming

Start with [Python](01-python.md), then [Bash](02-bash.md), [Git](03-git.md), [GitHub](04-github.md), and [SQL](05-sql.md). Build one small project from [Project ideas](11-project-ideas.md) before moving into machine learning or data engineering.

Suggested sequence:

`Python → Bash → Git → GitHub → SQL → APIs → first project`

## Path B — Interested in data science / ML

Make sure you can manipulate tabular data in [Python](01-python.md) and [SQL](05-sql.md). Then work through [Maths & statistics](09-maths-statistics.md) and [ML model families](08-ml-model-families.md). Learn enough [Git](03-git.md) to keep experiments reproducible and enough [Docker](07-docker.md) to understand how models can be packaged.

Suggested sequence:

`Python → SQL → statistics → ML families → Git → projects → Docker`

## Path C — Interested in data engineering

Prioritise tools that help you move, store, transform, and operate data reliably. Start with [Bash](02-bash.md), [Git](03-git.md), [Python](01-python.md), and [SQL](05-sql.md), then move to [APIs](06-apis.md), [Docker](07-docker.md), and [Data engineering foundations](10-data-engineering.md).

Suggested sequence:

`Bash → Git → Python → SQL → APIs → Docker → data engineering foundations → projects`

## Path D — Already comfortable coding

Skim Python setup and Git to align terminology, then focus on gaps. A software engineering student may get the most value from SQL, statistics, ML model families, and data engineering concepts. A maths student may need more command-line, Git, packaging, and API practice.

## What “good enough” looks like

You do **not** need to memorise every command or algorithm. Early on, aim for these abilities:

- explain the idea in your own words;
- recognise when the tool or concept is relevant;
- complete a small task while consulting documentation;
- read an error message and identify your next debugging step;
- save your work in a reproducible form; and
- know where to go for deeper study.

## A note on notebooks

Jupyter notebooks are excellent for exploration and teaching, but data work also includes scripts, packages, tests, command-line tools, services, and scheduled pipelines. Learn notebooks, but do not let “I can run this cell” become the same thing as “I can run this project again next month.” See [Python](01-python.md), [Git](03-git.md), and [Docker](07-docker.md) for reproducibility practices.
